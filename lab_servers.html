Compute servers

  • There are 3 GPU compute nodes -
    1. Shakuntala1 (3 GTX1080, 40 cores) (Note:- ssh to shakuntala1 should be done using the IP Address 10.237.23.117 (ssh user@10.237.23.117))
    2. Shakuntala2 (6 GTX 1080, 64 cores) (ssh user@shakuntala2.cse.iitd.in)
    3. Ramanuja1 (1 V100, 40 cores) (ssh user@ramanuja1.cse.iitd.in)
  • We recommend users to use Anaconda for installing packages. Use the required cudatoolkit (if needed) in your conda environments. You can create multiple environments.
    Note:- WE PREFER NOT TO update the existing CUDA drivers on these systems. It may cause problems for other users using the same system.
  • If you are using the multi-GPU servers (shakuntalaX), then please use the server GPUs responsibly. Don’t hog all the GPUs unnecessarily. We recommend maximum 2 nodes on shakuntala2 per user at any time. If you need more, you should coordinate amongst yourselves on the WhatsApp group.
  • To connect to the internet from your terminal use the proxy scripts. More details can be found here (Courtesy: Anupam Sobti). This is an internal link. Using screen sessions is a good idea for working remotely.
  • Since the disk space is limited, you will get 35 GB of home space by default. However, you may use the scratch folder designated for you for keeping the larger datasets/ files/ folders. A link to your designated scratch folder should be present in your home folder.
  • If you are working in the shakuntala/ramanuja servers, then please take regular backup of your data in local machines/hpc/onedrive or any other persistent storage of your choice. You can request up to 2TB free home space in HPC through your advisor. Onedrive provides 1 TB free space for IITD users.
    NOTE: shakuntala/ramanuja servers are for purely compute purpose and not for storage. Your files and folders in /home are liable to be deleted if the disk space starts to get full. We will try to delete the older files on a best effort basis (no-guarantees).
  • DO NOT download large datasets/models from internet directly in the shakuntala/ramanuja servers. Download the dataset in your local/HPC first and then transfer to the shakuntala/ramanuja servers. You may consider using the research proxy for bulk download.
  • Multi-GPU server (shakuntalaX) server users may use the designated WhatsApp channel for inter-user communication and raising issues to the admin.

    In addition to discussing upcoming events, users of social networking sites are having public conversations at an unprecedented scale. This presents a unique opportunity to collect millions of naturally occurring conversations and investigate new data-driven techniques for conversational modeling.

    I have worked on unsupervised modeling of dialogue acts in Twitter [NAACL 2010]. By remaining agnostic about the set of classes, we are able to learn a model which provides insight into the nature of communication in a new medium.

    I have investigated the feasibility of automatically replying to status messages by adapting techniques from Statistical Machine Translation [EMNLP 2011b], using millions of naturally occurring Twitter conversations as parallel text. Although there are many differences between conversation and translation, with a few conversation-specific adaptations we are able to build response models which often generate appropriate replies to Twitter status posts. This work has several possible applications, including conversationally aware predictive text entry.
